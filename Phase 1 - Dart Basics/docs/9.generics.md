13. Generics

Generics let you write code that can work with different types while still keeping type safety.

You've already seen generics without necessarily noticing:

List<String>
List<int>
Map<String, dynamic>
Set<int>

Here, String, int, and dynamic are type arguments.


---

1. Why do we need generics?

Without generics, you might use dynamic:

dynamic value = 'Hello';

Now Dart doesn't know what type value should be.

With generics:

List<String> names = ['Nayeem', 'Rahim'];

Dart knows:

> This list should contain only Strings.



So this is an error:

names.add(10); // ❌

That's one of the biggest benefits of generics: type safety.


---

2. Generic classes

You can create your own generic class.

class Box<T> {
  T value;

  Box(this.value);
}

Here T is a type parameter.

Now we can create a box containing a String:

final nameBox = Box<String>('Nayeem');

Or an int:

final ageBox = Box<int>(21);

The same Box class works with different types.

Box<T>
  │
  ├── Box<String>
  └── Box<int>


---

3. Generic functions

Functions can also use generics.

T getFirst<T>(List<T> items) {
  return items.first;
}

Now:

final name = getFirst<String>(['Nayeem', 'Rahim']);

name is a String.

And:

final number = getFirst<int>([10, 20, 30]);

number is an int.

Dart can often infer the type, so you can simply write:

final name = getFirst(['Nayeem', 'Rahim']);


---

4. Multiple type parameters

You can have more than one:

class Pair<K, V> {
  K key;
  V value;

  Pair(this.key, this.value);
}

Then:

final user = Pair<String, int>('Nayeem', 21);

Here:

K → String
V → int

This pattern is useful when a class needs to work with multiple related types.


---

5. Generic constraints

Sometimes you want to restrict what type can be used.

For example:

T getValue<T extends num>(T value) {
  return value;
}

Now T must be a subtype of num.

So these work:

getValue<int>(10);
getValue<double>(10.5);

But a String doesn't:

getValue<String>('Hello'); // ❌

You probably won't need to write constraints frequently as a beginner, but you should recognize them.


---

🧠 The important part for Flutter

You don't need to become an expert at advanced generics right now.

You mainly need to understand:

List<String>
List<int>
Map<String, dynamic>

and recognize:

<T>

as a type parameter.

You'll encounter generics in Flutter APIs and packages constantly.

For example:

Future<String>

means:

> A Future that eventually produces a String.



And:

Future<List<User>>

means:

> A Future that eventually produces a List of User objects.



We'll use this heavily when we reach Future and asynchronous programming.

Quick mental model

Generics = "This code works with a type that I specify later."

For example:

List<T>

means:

> "I have a list of some type T."



Then:

List<String>

means:

> "T is String."



and:

List<int>

means:

> "T is int."
