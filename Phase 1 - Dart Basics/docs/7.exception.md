Phase 1 — Dart

12. Exceptions

Exceptions are Dart's way of handling situations where something goes wrong while your program is running.

For example:

int result = 10 ~/ 0;

You can't divide by zero, so Dart throws an exception.


---

1. try / catch

We can handle the problem instead of letting the program crash:

try {
  int result = 10 ~/ 0;
  print(result);
} catch (e) {
  print('Something went wrong: $e');
}

try → code that might fail.

catch → what to do if it fails.


---

2. on

You can catch a specific type of exception:

try {
  int result = 10 ~/ 0;
  print(result);
} on IntegerDivisionByZeroException {
  print('You cannot divide by zero.');
}

This is useful when you want different handling for different exception types.


---

3. finally

finally runs whether an exception happens or not.

try {
  print('Trying...');
} catch (e) {
  print('Error');
} finally {
  print('Finished');
}

Output:

Trying...
Finished


---

4. throw

You can create your own exception:

void checkAge(int age) {
  if (age < 18) {
    throw Exception('User must be 18 or older');
  }

  print('Access granted');
}

Then:

try {
  checkAge(15);
} catch (e) {
  print(e);
}


---

5. Custom exceptions

You can create your own exception class:

class InvalidAgeException implements Exception {
  final String message;

  InvalidAgeException(this.message);
}

Then:

void checkAge(int age) {
  if (age < 18) {
    throw InvalidAgeException('Age must be 18 or older');
  }
}

You don't need to focus heavily on custom exceptions yet. Just understand the idea.


---

🧠 Remember

try     → try something that might fail
catch   → handle the error
on      → handle a specific exception
finally → always execute this
throw   → create/raise an exception

Flutter connection

You'll eventually use exception handling when working with things like:

API requests

Database operations

File operations

Authentication

Network failures


For example, an API request might fail because there is no internet connection. Instead of letting the app crash, you'll catch the error and show an appropriate UI message.
