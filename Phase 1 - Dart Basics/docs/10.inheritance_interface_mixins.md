11. Inheritance, Interfaces & Mixins

This is an important OOP topic, but don't worry—we'll take it step by step.

There are three separate concepts:

1. Inheritance → extends


2. Interfaces → implements


3. Mixins → with



We'll start with inheritance.


---

11.1 Inheritance — extends

Inheritance allows one class to reuse or extend another class.

Example:

class Animal {
  void eat() {
    print('Animal is eating');
  }
}

Now create another class:

class Dog extends Animal {
  void bark() {
    print('Dog is barking');
  }
}

Because Dog extends Animal, a Dog gets the methods from Animal.

final dog = Dog();

dog.eat();
dog.bark();

Output:

Animal is eating
Dog is barking

So:

Animal
   ↑
   |
  Dog

Dog inherits from Animal.


---

11.2 Why use inheritance?

Imagine you have:

class Animal {
  String name;

  Animal(this.name);

  void eat() {
    print('$name is eating');
  }
}

You could then create:

class Dog extends Animal {
  Dog(String name) : super(name);

  void bark() {
    print('$name is barking');
  }
}

Now:

final dog = Dog('Buddy');

dog.eat();
dog.bark();

The super(name) passes the value to the parent class constructor.

This is something you'll encounter when reading Flutter/Dart code.


---

11.3 Method overriding

A child class can change how an inherited method behaves.

class Animal {
  void sound() {
    print('Some animal sound');
  }
}

Now:

class Dog extends Animal {
  @override
  void sound() {
    print('Woof!');
  }
}

Then:

final dog = Dog();

dog.sound();

Output:

Woof!

@override tells Dart:

> "I'm intentionally replacing a method inherited from the parent class."



You'll see @override very frequently in Flutter.

For example:

@override
Widget build(BuildContext context) {
  ...
}

We'll understand that properly when we reach Flutter.


---

11.4 super

super refers to the parent class.

For example:

class Animal {
  void eat() {
    print('Eating');
  }
}

class Dog extends Animal {
  void test() {
    super.eat();
    print('Dog stuff');
  }
}

Calling:

Dog().test();

gives:

Eating
Dog stuff

So:

this  → current object
super → parent class


---

11.5 Interfaces — implements

Dart allows every class to act as an interface.

Example:

class Animal {
  void sound() {
    print('Animal sound');
  }
}

Another class can implement it:

class Dog implements Animal {
  @override
  void sound() {
    print('Woof!');
  }
}

The important difference:

extends

class Dog extends Animal

means:

> Dog inherits the implementation from Animal.



implements

class Dog implements Animal

means:

> Dog promises to provide the required interface of Animal.



So with implements, you generally need to provide the members yourself.


---

11.6 Mixins — with

Mixins are useful when you want to reuse behavior across unrelated classes.

Example:

mixin Swimming {
  void swim() {
    print('Swimming');
  }
}

Now:

class Fish with Swimming {}

And:

final fish = Fish();

fish.swim();

Output:

Swimming

You can also use multiple mixins:

mixin Swimming {
  void swim() {
    print('Swimming');
  }
}

mixin Flying {
  void fly() {
    print('Flying');
  }
}

class Duck with Swimming, Flying {}

Now:

final duck = Duck();

duck.swim();
duck.fly();


---

🧠 The key difference

Remember this:

Keyword	Main idea

extends	Inherit from a parent class
implements	Follow/provide a class's interface
with	Reuse behavior from a mixin


A simple mental model:

extends
   ↓
"I'm a specialized version of this."

implements
   ↓
"I promise to follow this contract."

with
   ↓
"I want this reusable behavior."
