Phase 1 — Dart

14. Future

Now we move from Generics → Future.

You already know that:

> Future<String> means a Future that eventually produces a String.



This is important because Flutter apps constantly do things that take time: API requests, reading files, database operations, etc.


---

1. Why do we need Future?

Normally, Dart executes code immediately:

String name = 'Nayeem';

print(name);

But imagine getting a username from an API.

The result isn't available immediately.

Request
   ↓
Wait...
   ↓
Server responds
   ↓
" Nayeem "

Instead of pretending the result is available immediately, Dart gives us a Future.

A Future basically means:

> "The value isn't ready yet, but it will be available later."




---

2. Simple example

Future<String> getName() {
  return Future.value('Nayeem');
}

The return type is:

Future<String>

Not:

String

Why?

Because the function doesn't directly give you the String.

It gives you a Future that will eventually give you the String.

Think:

Future<String>
      ↓
   "Nayeem"


---

3. Future<int>

The same idea works with other types:

Future<int> getAge() {
  return Future.value(21);
}

This means:

> "This function will eventually produce an int."



So:

Future<String>
Future<int>
Future<bool>
Future<List<String>>

are all possible.


---

4. Simulating a delay

Here's a more realistic example:

Future<String> getName() {
  return Future.delayed(
    Duration(seconds: 2),
    () => 'Nayeem',
  );
}

This means:

> Wait 2 seconds, then return "Nayeem".



The important part is that getName() doesn't block the whole program for 2 seconds.

It gives you a Future representing the work that will finish later.


---

5. The problem

Suppose:

Future<String> getName() {
  return Future.delayed(
    Duration(seconds: 2),
    () => 'Nayeem',
  );
}

Then:

final name = getName();

print(name);

You might expect:

Nayeem

But name is actually:

Future<String>

because the result isn't ready yet.


---

6. How do we get the actual value?

This is where the next topic comes in:

await

You can write:

final name = await getName();

Now name becomes:

String

So the flow is:

getName()
   ↓
Future<String>
   ↓ await
String
   ↓
"Nayeem"

We'll properly learn await in 15. async / await.


---

7. Future<void>

A Future doesn't always have to return a value.

For example:

Future<void> saveData() {
  return Future.delayed(
    Duration(seconds: 2),
    () {
      print('Data saved');
    },
  );
}

This means:

> "This operation will finish later, but it doesn't produce a value."



Common examples:

Future<void>
Future<String>
Future<int>
Future<bool>


---

8. Future with a generic

Notice the connection to Generics (13):

Future<String>

String is the type parameter.

Just like:

List<String>

means:

> A List containing Strings.



Future<String> means:

> A Future that eventually produces a String.



And:

Future<List<String>>

means:

> A Future that eventually produces a List of Strings.



This is extremely common in Flutter.

For example, an API might eventually give you:

Future<List<User>>

Meaning:

Future
  ↓
List<User>
  ↓
User
User
User
...


---

🧠 Mental model

Think of a Future like an order at a restaurant.

You order:

"Give me a pizza."

You don't immediately receive the pizza.

You receive something like:

Order #123

That order represents:

> "Your pizza will be available later."



That's similar to a:

Future<Pizza>

When it finishes, you get:

Pizza
