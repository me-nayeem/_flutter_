Phase 1 — Dart

8. Null Safety

Null safety is very important in Dart, and you'll see it everywhere in Flutter.

The basic idea is:

> A variable is not allowed to contain null unless you explicitly say that it can.



1. Non-nullable variables

String name = 'Nayeem';
int age = 21;

These cannot be null.

This is invalid:

String name = null; // ❌

Dart will complain because String means the variable must contain a String.


---

2. Nullable variables

If a value is allowed to be null, add ?.

String? name;
int? age;

Now this is valid:

name = null;
age = null;

This is exactly what you did in the previous exercise:

int? age

You were telling Dart:

> "age can either contain an integer or contain null."




---

3. Checking for null

You can use a normal condition:

if (age == null) {
  print('Age is not provided');
} else {
  print('Age is $age');
}

After checking, Dart can understand that age isn't null inside the else.


---

4. Null-aware operator ?.

Suppose:

String? name;

You can't safely do:

print(name.length); // ❌

because name could be null.

Instead:

print(name?.length);

If name is null, the result is null instead of causing an error.

For example:

String? name = 'Nayeem';

print(name?.length);

Output:

6


---

5. ?? — provide a fallback

This one is very important.

String? name;

print(name ?? 'Unknown');

If name is null, Dart uses 'Unknown'.

Think of it as:

> "Use the value on the left; if it's null, use the value on the right."



Example:

String? username;

String displayName = username ?? 'Guest';


---

6. ??=

This assigns a value only if the variable is currently null.

String? name;

name ??= 'Nayeem';

print(name);

Now:

Nayeem

But:

String? name = 'Rahim';

name ??= 'Nayeem';

print(name);

prints:

Rahim

because name wasn't null.


---

7. The ! operator

You'll eventually see:

String? name = 'Nayeem';

print(name!.length);

The ! means:

> "I guarantee this value isn't null."



But be careful.

If:

String? name = null;

print(name!.length);

your program will fail at runtime.

So don't use ! simply to silence Dart's warning. First ask yourself:

"Am I actually certain this value cannot be null here?"


---

Why this matters in Flutter

Imagine you get a user's name from an API:

String? username;

The server might provide a name—or it might not.

You could safely display:

Text(username ?? 'Unknown user')

This kind of null-aware code is extremely common in Flutter.


---

⭐ One thing I want you to understand

There are two different questions:

"Can this value be null?"

String?

"What should I do if it is null?"

You then choose something like:

?

or

??

or an explicit:

if (value == null)

or, when you genuinely know it's impossible:

!

That's the core of Dart null safety.
